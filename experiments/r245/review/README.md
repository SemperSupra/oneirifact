# R245 independent motion review

This lane reviews original authored activity intent and evaluated consumer poses. It does not supply captured human motion or qualify realism. Its numerical thresholds are provisional engineering criteria fixed before observing the new consumer results.

## Architecture findings

Measure morphology and sole landmarks after source shape edits and joint refitting, then bind motion. Keep the immutable source definition, resolved activity instance, desired targets, evaluated pose observations, and qualification receipt separate. An exported animation transports a result; it does not establish contact, realistic gait, tissue mechanics, or safe human joint ranges. The [glTF specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html) deliberately separates runtime asset transport from authoring information. Preserve editable native authoring data and the original intent beside baked transport.

Use the existing native IK, action, and NLA machinery through a thin adapter. [MakeHuman's rig documentation](https://static.makehumancommunity.org/mpfb/docs/characters/rig.html) describes default, game-engine, CMU MB, and Mixamo rig choices. Choosing a named rig does not automatically solve contact-aware retargeting. In the admitted source, intermediate `.02` thigh, shin, and arm bones must retain their bind-relative orientation when they represent subdivisions of one anatomical segment. Four independent hinge joints can otherwise make a thigh bend in its middle while preserving every individual bone length.

[Blender's Bake Action documentation](https://docs.blender.org/manual/en/dev/editors/nla/editing/strip.html) describes baking final constraint/driver evaluation into frame keys with visual keying. [Its glTF export documentation](https://docs.staging.blender.org/manual/en/latest/addons/scene_gltf2.html) separates action and NLA export modes. Record the chosen mode and actual pinned Blender version, then independently reopen exported clips and compare evaluated poses. Documentation alone does not establish that a particular version and action-slot configuration replay correctly.

Footwear must retain measured heel and forefoot stack heights, foot dimensions, toe articulation, and separate support footprints. Calibrate sole offsets once in a standing pose and transform them with the actual shoe. Subtracting world-vertical stack heights after each foot rotation changes the shoe's geometry. Heel strike, flat support, toe-off, swing, and the travelling loop boundary need independent one-sided continuity probes. A smooth-looking sampled loop can conceal a jump between samples. A platform's forefoot stack reduces pitch relative to a heel of the same total height; sole thickness alone cannot predict a person's gait. The [2018 heel/size study](https://pubmed.ncbi.nlm.nih.gov/29772495/) explicitly compared fixed heel height with a shoe-size-dependent height chosen to hold plantar flexion constant; it is a contextual reference, not a universal gait generator or admitted motion dataset.

Hand-to-mouth tasks require an actual mouth/prop target in the posed body's frame, calibrated grip geometry, and independent surface-contact measurements. A jaw-relative proxy or an authored wrist target is only a prototype. Seats and tubs likewise require measured support geometry and actual body clearances. Masked upper-body composition preserves lower-body targets only by construction; it does not prove whole-body contacts or balance. Keep arbitrary crossfades and aquatic mechanics unsupported until they have a consumer and critic. No breathing, soft tissue, or organ behavior is established by skeletal replay.

## Executable critics

`critic.py` consumes `oneirifact.motion-consumer-observations/v1`. It never imports compiler, FK, Blender, or solver code. It measures anatomical leg lengths, intended reachability, actual ankle/pelvis tracking, world planted-marker drift and speed, active contact height, ground penetration, rigid heel-to-forefoot distance, intermediate bone rotation, hand target residual, and root-compensated loop closure. Unsupported collision, anatomy, dynamics, seat/prop contacts, tissue behavior, and realism remain `NOT_RUN`. Missing observations cannot produce an acceptance result.

`compiler_audit.py` uses only the compiler's public API. At all four authored gait joins on both legs, it samples each side of the boundary by 10 microseconds and compares positions, rotations, and one-sided velocity. It also checks rigid heel-to-forefoot distance over sampled walk/jog/run cycles. This is an intent screen; measured Blender poses are still required.

`analytic_oracles.py` independently constructs exact geometric controls. Positive stationary and travelling-loop cases must survive; introduced planted sliding, segment stretching, unreachable targets, endpoint jumps, and intermediate-bone rotation must fail. Quaternion sign reversal must represent the same pose. Empty frames and duplicate times must be invalid.

## Existing retargeting work for a future donor comparison

[BVH and FBX Retargeter](https://github.com/Diffeomorphic/retarget_bvh) is a concrete code donor candidate. The [official MakeHuman FAQ](https://static.makehumancommunity.org/oldsite/faq/what_happened_to_makewalk.html) marks MakeWalk deprecated and points to this author's successor. The [author's August 2026 release announcement](https://diffeomorphic.blogspot.com/2026/08/diffeomorphic-add-ons-version-520.html?m=0) reports version 5.2.0 tested with Blender 3.6 and 5.2. Direct upstream file reads on 2026-11-28 found `blender_manifest.toml` version `5.2.0`, minimum Blender `4.2.0`, and `SPDX:GPL-2.0-or-later`; [LICENSE](https://github.com/Diffeomorphic/retarget_bvh/blob/master/LICENSE) independently states GPL version 2 or later. The observed Git blob IDs are manifest `33cec2c0c3d0021d8ff3d8bd64bcf83756a451d8` and license `f8b71064e7a2da9b556742ac289a207ea27d6700`. These are source observations, not an immutable release qualification. Preserve GPL notices and applicable source obligations if code is redistributed. No code was copied, installed, or adopted here. A bounded intake should pin a complete revision and compare one licensed captured sequence before expanding.

[Contact-Aware Retargeting of Skinned Motion, ICCV 2021](https://openaccess.thecvf.com/content/ICCV2021/html/Villegas_Contact-Aware_Retargeting_of_Skinned_Motion_ICCV_2021_paper.html) treats self-contact, ground contact, target geometry, and interpenetration jointly. [ReConForM, 2025](https://arxiv.org/abs/2502.21207) uses rigged mesh landmarks and adaptive contact features across morphologies, including interactions and uneven terrain. These support preserving semantic contacts when adapting motion. Neither paper's availability establishes reusable implementation or motion-data rights. A future comparison should inspect the actual released code, model, data, dependencies, and terms before adoption; this review copied no implementation or dataset.

The subsequent source-only intake is recorded in `retarget-donor-intake.json`: upstream tag `version_5_2_0` resolves to `8501d53f66fffa8d2574a01532c30e195c8d2998`. It is not a drop-in match for this project's source rig: its built-in MakeHuman profile uses six bone names absent from the admitted 163-bone rig. A small explicit role/reference-pose adapter is required. Original CMU ASF/AMC also requires a separately qualified format bridge; the addon directly accepts BVH/FBX/glTF. The receipt bounds the next comparison to two named captures and two existing stature variants on standard public runners. That next comparison has not been launched or adopted.
